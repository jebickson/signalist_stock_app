# Background Jobs & Notifications

### 1. Overview

Signalist integrates **Inngest** and **Nodemailer** to support background processing and email notifications.

These integrations help the application handle tasks that do not need to run directly inside a user's browser interaction.

* **Inngest:** Coordinates background functions and workflows.
* **Nodemailer:** Sends emails through an SMTP email account.

### 2. Technologies Used

| Technology | Purpose                                    |
| ---------- | ------------------------------------------ |
| Inngest    | Background jobs and workflow orchestration |
| Nodemailer | Email delivery                             |
| Next.js    | Application and API route integration      |
| MongoDB    | Application data storage                   |

### 3. Inngest Integration

Inngest is used to coordinate background functions and application workflows.

It allows the application to process tasks separately from normal frontend requests.

#### Main responsibilities

* Execute background functions.
* Coordinate application workflows.
* Support automated processing.
* Integrate background tasks with the Next.js application.

#### Inngest API Route

Signalist provides an Inngest handler through the following route:

```
/api/inngest
```

This route connects the Next.js application with the Inngest platform.

#### Local Development

Start the Signalist application:

```
npm run dev
```

Open another terminal and run:

```
npx inngest-cli@latest dev
```

Local Inngest development dashboard:

```
http://localhost:8288
```

### 4. Nodemailer Integration

Nodemailer is used to send emails through an SMTP-supported email account.

#### Main responsibilities

* Send application emails.
* Support automated email notifications.
* Deliver email content generated by application workflows.

#### Environment Configuration

The following environment variables are used:

```
NODEMAILER_EMAIL=your_email@example.com
NODEMAILER_PASSWORD=your_app_specific_password
```

| Variable              | Description                         |
| --------------------- | ----------------------------------- |
| `NODEMAILER_EMAIL`    | Email account used to send messages |
| `NODEMAILER_PASSWORD` | SMTP authentication password        |

Use an app-specific password where required by your email provider. Do not publish real credentials in documentation or source control.

### 5. Background Workflow Architecture

The general workflow can be represented as:

```
Application Event
       |
       v
Next.js Backend
       |
       v
Inngest Handler
       |
       v
Background Function
       |
       v
Nodemailer
       |
       v
Recipient Email
```

This represents the integration concept. Actual workflow triggers, function names, and execution conditions depend on the implementation in the repository.

### 6. Local Testing

Follow these steps to test the integrations during development:

1. Configure the required environment variables.
2. Start the Next.js development server.
3. Start the Inngest development server in a separate terminal.
4. Open the Inngest dashboard.
5. Trigger the relevant application workflow.
6. Review execution results and errors.
7. Verify email delivery using the configured email account.

### 7. Production Deployment

For production deployment:

* Configure Inngest for the deployed application.
* Set up the production Inngest connection.
* Configure SMTP credentials securely.
* Add the required environment variables to Vercel.
* Verify that background functions execute successfully.
* Test email delivery before releasing changes.

### 8. Error Handling & Security

Recommended practices:

* Keep SMTP credentials private.
* Never commit `.env` files.
* Handle email delivery failures appropriately.
* Monitor background function execution.
* Avoid exposing internal error details to users.
* Test workflows before deploying to production.

### 9. Conclusion

Inngest and Nodemailer extend Signalist beyond standard request-response operations.

Inngest coordinates background workflows, while Nodemailer provides email delivery. Together, these integrations support automated application processes and notification functionality.
